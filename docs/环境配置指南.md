## 环境概述

DocRadar支持两种运行环境，它们使用不同的IP地址和数据存储位置：

- **测试环境**：
  - IP地址: **严格限制为 `127.0.0.1`**
  - 数据存储路径: `./data/test/`
  - 默认启用调试模式
  - 通常用于开发和测试
  - **只能通过 localhost/127.0.0.1 访问**

- **生产环境**：
  - IP地址: **严格限制为 `192.168.0.110`**
  - 数据存储路径: `./data/production/`
  - 默认禁用调试模式
  - 用于正式部署和使用
  - **只能通过 192.168.0.110 访问**

两个环境完全隔离，测试环境的操作不会影响生产环境的数据，且每个环境都只能通过其指定的IP地址访问。

> **重要说明**：最新版本中，我们实施了严格的IP访问限制，确保每个环境只能通过其指定的IP地址访问。这意味着测试环境 **只能** 通过127.0.0.1访问，生产环境 **只能** 通过192.168.0.110访问。

## 环境配置

环境通过环境变量 `DOCRADAR_ENV` 进行区分，并且与访问IP地址严格绑定：

- `DOCRADAR_ENV=test`：测试环境（默认值）- 绑定到127.0.0.1
- `DOCRADAR_ENV=production`：生产环境 - 绑定到192.168.0.110

系统配置根据环境变量自动加载不同的设置：

```python
# config.py 中的配置逻辑
ENV = os.environ.get('DOCRADAR_ENV', 'test')  # 默认为测试环境

# 根据环境设置不同的主机地址
if ENV == 'test':
    HOST = '127.0.0.1'  # 测试环境严格绑定到127.0.0.1
    PORT = 5000
else:  # production
    HOST = '192.168.0.110'  # 生产环境严格绑定到192.168.0.110
    PORT = 5000

# 数据库配置也会根据环境变化
if ENV == 'test':
    DB_NAME = 'docradar_test.db'
else:
    DB_NAME = 'docradar_prod.db'
```

## 用户账户与管理员密钥

在最新版本中，我们进一步强化了环境隔离，为每个环境使用独立的用户账户文件和管理员密钥配置文件：

- **测试环境**：
  - 用户账户文件：`users_test.json`
  - 管理员密钥文件：`admin_config_test.json`

- **生产环境**：
  - 用户账户文件：`users_production.json`
  - 管理员密钥文件：`admin_config_production.json`

这确保了测试环境的用户操作不会影响生产环境的用户数据，反之亦然。每个环境都有自己独立的用户账户和管理员密钥。

### 管理员密钥工具

可以使用 `show_admin_key.py` 工具来查看和设置特定环境的管理员密钥：

```bash
# 查看测试环境的管理员密钥
python show_admin_key.py --env test

# 查看生产环境的管理员密钥
python show_admin_key.py --env production

# 为测试环境设置新的管理员密钥
python show_admin_key.py --set YOUR_NEW_KEY --env test

# 为生产环境设置新的管理员密钥
python show_admin_key.py --set YOUR_NEW_KEY --env production

# 生成随机密钥并保存到测试环境
python show_admin_key.py --generate --env test

# 重置测试环境的管理员密码
python show_admin_key.py --reset-admin-password --env test

# 重置生产环境的管理员密码
python show_admin_key.py --reset-admin-password --env production
```

### 用户账户管理

系统会根据当前运行的环境自动选择正确的用户文件：

- 在测试环境中，用户登录、注册和管理操作都只会影响 `users_test.json` 文件
- 在生产环境中，用户登录、注册和管理操作都只会影响 `users_production.json` 文件

这样可以确保在测试环境中可以自由创建测试账户而不会影响生产环境的真实用户数据。

## 日志文件

系统日志根据环境自动分离，便于分别查看测试环境和生产环境的运行情况：

- **测试环境**日志文件：`./tmp/docRadar_YYYYMMDD_test.log`
- **生产环境**日志文件：`./tmp/docRadar_YYYYMMDD.log`

日志文件按日期自动创建，系统会自动清理7天前的旧日志。各环境的日志不会相互混淆，方便分析问题。

日志中包含详细的系统运行信息，如文档上传、搜索、用户操作等，在出现问题时可以查看相应环境的日志进行诊断。

## 直接运行Python应用

### Windows环境下

**启动测试环境** (默认)：
```powershell
# 不需要设置环境变量，默认为测试环境
python app.py

# 应用将绑定到127.0.0.1:5000，只能通过localhost访问
```

**启动生产环境**：
```powershell
# CMD命令提示符
set DOCRADAR_ENV=production
python app.py

# 或者在PowerShell中
$env:DOCRADAR_ENV="production"
python app.py

# 应用将绑定到192.168.0.110:5000，只能通过此IP访问
```

### Linux/Mac环境下

**启动测试环境** (默认)：
```bash
python app.py

# 应用将绑定到127.0.0.1:5000，只能通过localhost访问
```

**启动生产环境**：
```bash
# 先设置环境变量，再运行
export DOCRADAR_ENV=production
python app.py

# 或者一行命令完成
DOCRADAR_ENV=production python app.py

# 应用将绑定到192.168.0.110:5000，只能通过此IP访问
```

### 验证当前环境

启动后，观察控制台日志，会显示当前环境信息和绑定地址：
```
当前环境: test|production, 主机: 127.0.0.1|192.168.0.110
应用启动于 127.0.0.1:5000|192.168.0.110:5000, 环境: test|production
```

在网页界面上，环境信息会显示在页面顶部：
- 测试环境：显示蓝色提示条 "测试环境 (127.0.0.1:5000)"
- 生产环境：显示红色提示条 "生产环境 (192.168.0.110:5000)"

## Docker部署

### 基本说明

DocRadar的Docker配置支持同时运行测试和生产两个环境，使用不同的容器、端口和IP绑定：

- **生产环境容器**: 
  - 名称: `docradar`
  - 端口: 5000
  - IP绑定: **严格限制为192.168.0.110**
  - 访问地址: http://192.168.0.110:5000/

- **测试环境容器**: 
  - 名称: `docradar_test`
  - 端口: 5001
  - IP绑定: **严格限制为127.0.0.1**
  - 访问地址: http://127.0.0.1:5001/

### 配置文件

`docker-compose.yml` 已经预先配置好了两个环境，并进行了严格的IP绑定：

```yaml
version: '3'

services:
  # 生产环境容器
  docradar:
    build: .
    image: docradar:latest
    container_name: docradar
    restart: always
    ports:
      - "192.168.0.110:5000:5000"  # 只绑定到192.168.0.110
    volumes:
      - ./data/production/uploads:/app/data/uploads
      - ./data/production/db:/app/data/db
      - ./data/production/logs:/app/data/logs
      - ./users_production.json:/app/users.json
      - ./admin_config_production.json:/app/admin_config.json
    environment:
      - SECRET_KEY=Hwkqzxsl9eOirB2MNmK3P7cTndWQ1a6y
      - ADMIN_KEY=IEbdFkZWuwm4zHpUy61BX9gD7aj3qoti
      - DOCRADAR_ENV=production
      - FLASK_DEBUG=0
    command: gunicorn --workers=4 --bind=0.0.0.0:5000 app:app
    networks:
      docradar_net:
        aliases:
          - docradar-prod

  # 测试环境容器  
  docradar_test:
    build: .
    image: docradar:latest
    container_name: docradar_test
    restart: always
    ports:
      - "127.0.0.1:5001:5000"  # 只绑定到127.0.0.1
    volumes:
      - ./data/test/uploads:/app/data/uploads
      - ./data/test/db:/app/data/db
      - ./data/test/logs:/app/data/logs
      - ./users_test.json:/app/users.json
      - ./admin_config_test.json:/app/admin_config.json
    environment:
      - SECRET_KEY=TestSecretKeyDifferentFromProduction
      - ADMIN_KEY=TestAdminKeyDifferentFromProduction
      - DOCRADAR_ENV=test
      - FLASK_DEBUG=1
    command: gunicorn --workers=2 --bind=0.0.0.0:5000 app:app
    networks:
      docradar_net:
        aliases:
          - docradar-test

# 创建自定义网络
networks:
  docradar_net:
    driver: bridge
```

**特别说明**：Docker配置中，我们为每个环境使用了独立的用户文件和管理员配置文件，这确保了两个环境的完全隔离。

### 部署步骤

**同时启动两个环境**：
```bash
docker-compose up -d
```

**仅启动生产环境**：
```bash
docker-compose up -d docradar
```

**仅启动测试环境**：
```bash
docker-compose up -d docradar_test
```

### 验证容器状态

```bash
# 查看运行中的容器
docker ps

# 查看容器日志
docker logs docradar
docker logs docradar_test
```

### 访问地址

现在每个环境都有严格的访问限制：

- **测试环境**：只能通过 http://127.0.0.1:5001/ 访问
- **生产环境**：只能通过 http://192.168.0.110:5000/ 访问

尝试通过其他IP地址访问将无法连接到服务。

不同环境的数据完全隔离存储，确保测试不会影响生产数据：

### 直接运行方式

- **测试环境**：
  - 数据目录：`./data/test/`
  - 数据库文件：`./data/test/db/docradar_test.db`
  - 上传文件：`./data/test/uploads/`
  - 用户文件：`./users_test.json`
  - 管理员配置：`./admin_config_test.json`

- **生产环境**：
  - 数据目录：`./data/production/`
  - 数据库文件：`./data/production/db/docradar_prod.db`
  - 上传文件：`./data/production/uploads/`
  - 用户文件：`./users_production.json`
  - 管理员配置：`./admin_config_production.json`

### Docker部署方式

- **测试环境**：
  - 数据目录映射：`./data/test/` → 容器内 `/app/data/`
  - 用户文件映射：`./users_test.json` → 容器内 `/app/users.json`
  - 管理员配置映射：`./admin_config_test.json` → 容器内 `/app/admin_config.json`
  - 端口映射：127.0.0.1:5001 → 容器内 5000
  - 只能通过 127.0.0.1 访问

- **生产环境**：
  - 数据目录映射：`./data/production/` → 容器内 `/app/data/`
  - 用户文件映射：`./users_production.json` → 容器内 `/app/users.json`
  - 管理员配置映射：`./admin_config_production.json` → 容器内 `/app/admin_config.json`
  - 端口映射：192.168.0.110:5000 → 容器内 5000
  - 只能通过 192.168.0.110 访问

## 常见问题与解决方案

### 1. 无法通过特定IP访问环境

**症状**：尝试通过某个IP地址（如192.168.0.110）访问应用，但显示"无法连接到服务器"

**解决方案**：
- 确认正在使用正确的环境变量启动应用
- 检查应用日志，确认绑定的IP地址和端口
- 确保配置文件中的IP地址与您的网络设置匹配
- 如需更改IP地址，请编辑config.py文件中的HOST变量

### 2. 环境变量设置问题

**症状**：设置环境变量但未生效，系统仍运行在默认环境中

**解决方案**：
- Windows环境下，确保在同一命令行窗口中设置变量后立即运行应用
- Linux/Mac环境下，使用`export`命令或在同一行设置变量并运行
- 验证方法：观察启动日志，应显示 `应用启动于 [预期IP]:[端口], 环境: [预期环境]`

### 3. Docker容器IP绑定问题

**症状**：Docker容器启动成功，但无法通过指定IP访问

**解决方案**：
- 确认您的机器实际拥有docker-compose.yml中指定的IP地址
- 检查Docker网络设置：`docker network inspect docradar_net`
- 如果您的机器没有192.168.0.110 IP地址，需要修改docker-compose.yml中的IP绑定
- 对于本地测试，可考虑将生产环境也绑定到127.0.0.1但使用不同端口

### 4. 希望在同一IP上同时运行测试和生产环境

**症状**：需要在同一IP地址上运行两个环境（例如，在没有多个IP的单机上测试）

**解决方案**：
- 修改config.py中的IP设置，使两个环境使用相同IP但不同端口
- 编辑docker-compose.yml，使用相同IP但不同端口绑定
- 记得修改环境指示器，以便通过端口区分环境

### 5. 切换环境后数据丢失

**症状**：切换环境后看不到之前环境的数据

**解决方案**：
- 这是预期行为 - 两个环境使用完全不同的数据存储
- 测试环境数据在`./data/test/`目录，使用`users_test.json`
- 生产环境数据在`./data/production/`目录，使用`users_production.json`
- 如果需要迁移数据，可以手动复制相应的数据库文件和用户文件

### 6. 忘记管理员密码

**症状**：无法使用管理员账户登录系统

**解决方案**：
- 使用`show_admin_key.py`工具重置管理员密码
- 根据需要指定环境：
  ```bash
  # 重置测试环境管理员密码
  python show_admin_key.py --reset-admin-password --env test
  
  # 重置生产环境管理员密码
  python show_admin_key.py --reset-admin-password --env production
  ```
- 系统会生成一个新的随机密码，请立即记录并登录后更改

## DocRadar 环境配置指南

### 目录结构

DocRadar 使用以下目录结构来分离生产和测试数据：

```
DocRadar/
├── data/
│   ├── production/   # 生产环境数据
│   │   ├── uploads/  # 上传的文档
│   │   ├── db/       # 数据库文件
│   │   └── logs/     # 日志文件
│   └── test/         # 测试环境数据
│       ├── uploads/  # 测试环境上传的文档
│       ├── db/       # 测试环境数据库文件
│       └── logs/     # 测试环境日志文件
├── users_production.json  # 生产环境用户数据
├── users_test.json        # 测试环境用户数据
├── admin_config_production.json  # 生产环境管理员配置
└── admin_config_test.json        # 测试环境管理员配置
```

### 命令行环境参数

现在可以通过命令行参数指定运行环境，而不是使用环境变量：

1. 直接通过 Python 运行：

```bash
# 测试环境（默认）
python app.py

# 明确指定测试环境
python app.py --env test
python app.py -e test

# 生产环境
python app.py --env production
python app.py -e production
```

2. 使用启动脚本运行（推荐）：

```bash
# 测试环境
python run.py -e test

# 生产环境
python run.py -e production
```

3. 使用 Docker：

使用 Docker Compose 部署时会自动设置相应的环境参数：

```bash
# 启动生产环境
docker-compose up docradar

# 启动测试环境
docker-compose up docradar_test
```

### 环境变量设置（向后兼容）

为了兼容性，系统仍然支持通过环境变量 `DOCRADAR_ENV` 指定环境。如果同时设置了环境变量和命令行参数，命令行参数优先。
